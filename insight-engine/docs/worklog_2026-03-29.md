## 貼圖系統 Bug 修復（最高優先）

### 問題診斷過程
ZIP 上傳出現 `ADM-ZIP: Invalid or unsupported zip format. No END header found`

排查流程：
1. `FormData` 解析失敗 → 改用 `application/octet-stream` 直接傳 binary
2. `proxy.ts` 未 bypass `octet-stream` → 補上繞過條件
3. `arrayBuffer()` 未正確讀取 → 改為明確讀取 `fileBuffer`
4. 空 buffer 診斷 → 加入空值檢查回傳明確錯誤
5. ZIP magic bytes 驗證（0x50 0x4B）→ 非 ZIP 格式立即回報 hex + 大小
6. **根本原因確認**：Zeabur runtime log 顯示 `Request body exceeded 10MB — Only the first 10MB will be available`，ZIP 為 27.4MB，被截斷後 EOCD record 缺失

### 根本原因修復
`next.config.ts` 的 `experimental` 區塊設定 `proxyClientMaxBodySize: '50mb'`

途中遭遇的 build 失敗：
- `middlewareClientMaxBodySize` 被棄用（Next.js 16.1.7 改名為 `proxyClientMaxBodySize`）
- `serverBodySizeLimit` 不在 `ExperimentalConfig` 型別中 → 移除

最終設定：
```typescript
experimental: {
  proxyClientMaxBodySize: '50mb',
}
```

### 上傳失敗後自動清理
ZIP 上傳失敗時，自動呼叫 `DELETE /api/super-admin/stickers/{packId}` 清除已建立的空貼圖包

## DB 資料修復

### 問題
`maoxingtianxia-mvp-survey` 問卷從 20 題暴增至 155 題，全部重複

### 根本原因
`seed_branching.js` 無 `ON CONFLICT` 保護，重複執行約 17 次 → 135 筆重複 question row

### 修復
新增 `scripts/dedup-questions.mjs`：
- 使用 PostgreSQL `ROW_NUMBER() OVER (PARTITION BY survey_id, key ORDER BY created_at ASC)`
- 每個 key 保留最早一筆，刪除其餘
- 成功刪除 135 筆，問卷恢復 20 題
- 確認其他問卷無重複問題
