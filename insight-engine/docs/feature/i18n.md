# i18n 國際化

## 目標

讓平台支援多語言，涵蓋後台 UI、填答頁面、問卷系統介面。

## 技術選型

**next-intl** — 與 Next.js App Router 最相容

```bash
npm install next-intl
```

## 兩層 i18n

### Layer 1：系統 UI（按鈕、提示、錯誤訊息）

由 next-intl 處理，翻譯檔放在 `messages/` 資料夾：

```
messages/
  zh-TW.json   ← 預設（繁體中文）
  en.json
  ja.json
```

### Layer 2：問卷內容（題目、選項、說明）

問卷內容存在 DB，需要多語言欄位支援：

```sql
-- 方案 A：新增 translations JSONB 欄位（較簡單）
ALTER TABLE questions ADD COLUMN IF NOT EXISTS translations JSONB;
-- { "en": { "content": "...", "options": [...] }, "ja": { ... } }

-- 方案 B：獨立 question_translations 表（較彈性）
CREATE TABLE question_translations (
  question_id UUID REFERENCES questions(id),
  locale TEXT NOT NULL,
  content TEXT NOT NULL,
  options JSONB NOT NULL,
  PRIMARY KEY (question_id, locale)
);
```

## 路由設計

```
/survey          → 依瀏覽器語言自動判斷
/survey?lang=en  → 強制英文
/{org}/{slug}?lang=ja → 日文填答
```

## 實作優先順序

1. 系統 UI 文字抽出到翻譯檔（繁中 + 英文）
2. 填答頁語言切換按鈕
3. 問卷內容多語言欄位（DB migration）
4. 後台問卷編輯支援多語言輸入
5. AI 問卷生成支援指定語言輸出

## 注意事項

- `NEXT_PUBLIC_DEFAULT_LOCALE=zh-TW` 加入 ENV
- middleware 需處理 locale prefix routing
- 問卷 slug 不需要語言前綴（slug 是 URL 識別碼，不翻譯）
- gameTitles、resultConfig 也需要多語言版本
